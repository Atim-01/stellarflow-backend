# Relayer Key Encryption System 🔐

## Overview

This document describes the KMS-managed envelope encryption system for relayer Ed25519 private keys implemented in the StellarFlow backend.

## Security Architecture

### Envelope Encryption Pattern

The system uses **envelope encryption** with AWS KMS to protect relayer private keys:

```
┌─────────────────────────────────────────────────────────────┐
│                     AWS KMS (HSM-backed)                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  Master Key (KMS_ENVELOPE_KEY_ID)                    │  │
│  │  • Never leaves AWS HSM                               │  │
│  │  • Used to encrypt/decrypt DEKs only                  │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    Encrypts/Decrypts
                              ↓
┌─────────────────────────────────────────────────────────────┐
│              Data Encryption Keys (DEKs)                    │
│  • 256-bit AES keys generated by KMS                        │
│  • One unique DEK per relayer                               │
│  • Rotated every 90 days automatically                      │
│  • Stored encrypted in database (encryptedDek column)       │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    Encrypts/Decrypts
                              ↓
┌─────────────────────────────────────────────────────────────┐
│            Relayer Ed25519 Private Keys                     │
│  • Encrypted with AES-256-GCM using DEK                     │
│  • Stored in database (encryptedPrivateKey column)          │
│  • Never stored in plaintext                                │
│  • Zero-wiped from memory after use                         │
└─────────────────────────────────────────────────────────────┘
```

### Key Security Features

✅ **Zero Unencrypted Keys in Database**
- All private keys encrypted with AES-256-GCM
- Database backups contain only encrypted data
- Verification script ensures no plaintext leakage

✅ **KMS-Protected Encryption Keys**
- Data Encryption Keys (DEKs) protected by AWS KMS HSM
- Master key never leaves AWS infrastructure
- All KMS operations logged in CloudTrail

✅ **Automatic Key Rotation**
- DEKs rotated every 90 days automatically
- Scheduled job runs daily at 2:00 AM UTC
- Re-encryption happens transparently

✅ **Memory Security**
- Plaintext keys loaded into secure vault (in-memory only)
- Scoped access with context tokens
- Automatic zero-wipe after use

✅ **Audit Trail**
- All key operations logged
- Rotation events tracked
- Failed operations recorded

## Database Schema

```sql
-- Relayer table with encrypted key storage
ALTER TABLE "Relayer" ADD COLUMN "publicKey" VARCHAR(64);
ALTER TABLE "Relayer" ADD COLUMN "encryptedPrivateKey" TEXT;
ALTER TABLE "Relayer" ADD COLUMN "encryptedDek" TEXT;
ALTER TABLE "Relayer" ADD COLUMN "dekVersion" INTEGER DEFAULT 1;
ALTER TABLE "Relayer" ADD COLUMN "dekEncryptedAt" TIMESTAMPTZ(3);
ALTER TABLE "Relayer" ADD COLUMN "dekRotationScheduledAt" TIMESTAMPTZ(3);
ALTER TABLE "Relayer" ADD COLUMN "keyGeneratedAt" TIMESTAMPTZ(3);

CREATE INDEX "Relayer_dekRotationScheduledAt_idx" 
  ON "Relayer"("dekRotationScheduledAt");
```

### Column Descriptions

| Column | Type | Description |
|--------|------|-------------|
| `publicKey` | VARCHAR(64) | Hex-encoded Ed25519 public key (plaintext, used for signature verification) |
| `encryptedPrivateKey` | TEXT | AES-256-GCM encrypted private key (format: iv + ciphertext + tag in hex) |
| `encryptedDek` | TEXT | KMS-encrypted Data Encryption Key (base64) |
| `dekVersion` | INTEGER | DEK version number (increments on rotation) |
| `dekEncryptedAt` | TIMESTAMPTZ | When current DEK was encrypted by KMS |
| `dekRotationScheduledAt` | TIMESTAMPTZ | When next DEK rotation is scheduled (90 days from dekEncryptedAt) |
| `keyGeneratedAt` | TIMESTAMPTZ | When the key pair was first generated |

## Environment Configuration

### Required Environment Variables

```bash
# AWS KMS Configuration
KMS_ENVELOPE_KEY_ID=arn:aws:kms:us-east-1:123456789012:key/your-key-id
AWS_REGION=us-east-1

# AWS Credentials (via environment, IAM role, or credentials file)
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
```

### KMS Key Setup

1. **Create KMS Key in AWS Console:**
   ```bash
   aws kms create-key \
     --description "StellarFlow Relayer Key Envelope Encryption" \
     --key-usage ENCRYPT_DECRYPT \
     --origin AWS_KMS
   ```

2. **Create Key Alias:**
   ```bash
   aws kms create-alias \
     --alias-name alias/stellarflow-relayer-envelope \
     --target-key-id <key-id>
   ```

3. **Set IAM Policy:**
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": [
           "kms:GenerateDataKey",
           "kms:Decrypt"
         ],
         "Resource": "arn:aws:kms:us-east-1:123456789012:key/*"
       }
     ]
   }
   ```

4. **Set Environment Variable:**
   ```bash
   export KMS_ENVELOPE_KEY_ID=arn:aws:kms:us-east-1:123456789012:key/your-key-id
   ```

## DEK Rotation

### Automatic Rotation Schedule

- **Frequency:** Every 90 days
- **Job Schedule:** Daily at 2:00 AM UTC
- **Process:** 
  1. Finds all relayers with overdue DEK rotations
  2. Decrypts private key with old DEK
  3. Generates new DEK via KMS
  4. Re-encrypts private key with new DEK
  5. Updates database with new encrypted data
  6. Schedules next rotation (90 days from now)

### Manual Rotation

Trigger manual rotation for testing or emergency scenarios:

```bash
# Dry run (no actual rotation)
curl -X POST http://localhost:3000/api/admin/relayers/keys/rotate-deks?dryRun=true \
  -H "X-Admin-Key: your-admin-key"

# Rotate up to 10 relayers
curl -X POST http://localhost:3000/api/admin/relayers/keys/rotate-deks?maxRelayers=10 \
  -H "X-Admin-Key: your-admin-key"

# Rotate all overdue relayers
curl -X POST http://localhost:3000/api/admin/relayers/keys/rotate-deks \
  -H "X-Admin-Key: your-admin-key"
```

## Using Relayer Keys in Code

### Generate and Store Key Pair

```typescript

const keyService = getRelayerKeyService();

const keyInfo = await keyService.generateAndStoreKeyPair(relayerId);
```

### Sign Transaction with Relayer Key

```typescript
import { getRelayerKeyService } from './services/relayerKeyService';
import { Keypair } from '@stellar/stellar-sdk';

const keyService = getRelayerKeyService();

// Method 1: Using withPrivateKey helper (recommended)
const signature = await keyService.withPrivateKey(relayerId, async (privateKey) => {
  const keypair = Keypair.fromSecret(privateKey);
  return keypair.sign(txHash);
});

// Method 2: Manual context management
const context = await keyService.retrievePrivateKey(relayerId);
try {
  const privateKey = keyService.getPrivateKeyFromVault(relayerId, context);
  const keypair = Keypair.fromSecret(privateKey);
  const signature = keypair.sign(txHash);
  // Use signature...
} finally {
  keyService.revokePrivateKey(relayerId, context);
}
```

### Validate Encrypted Key

```typescript
import { getRelayerKeyService } from './services/relayerKeyService';

const keyService = getRelayerKeyService();
const isValid = await keyService.validateEncryptedKey(relayerId);
console.log('Key validation:', isValid ? 'PASSED' : 'FAILED');
```

## Security Best Practices

### 1. KMS Key Management

- ✅ Use separate KMS keys for dev/staging/production
- ✅ Enable KMS key rotation (automatic key material rotation)
- ✅ Set up CloudWatch alarms for KMS API errors
- ✅ Review CloudTrail logs regularly
- ✅ Restrict KMS key access via IAM policies

### 2. Database Security

- ✅ Encrypt database at rest
- ✅ Use encrypted database backups
- ✅ Restrict database access to application only
- ✅ Enable database audit logging
- ✅ Regular backup testing

### 3. Application Security

- ✅ Always use `withPrivateKey()` helper for automatic cleanup
- ✅ Never log private keys or decrypted DEKs
- ✅ Monitor failed decryption attempts
- ✅ Set up alerts for rotation failures

### Metrics to Monitor

1. **Rotation Health:**
   - Successful DEK rotations per day
   - Failed DEK rotations
   - Overdue rotation count

2. **KMS Operations:**
   - GenerateDataKey API calls
   - Decrypt API calls
   - KMS API errors

3. **Key Operations:**
   - Key generation requests
   - Key decryption requests
   - Validation failures

### Recommended Alerts

```yaml

- name: DEK rotation failure
  condition: failed_rotations > 0
```

## Troubleshooting

### Issue: Key Decryption Fails

**Symptoms:** `Failed to decrypt data key` error

**Solutions:**
1. Check AWS credentials are valid
2. Verify IAM policy allows `kms:Decrypt`
3. Confirm KMS key ID is correct
4. Check CloudTrail for KMS API errors

### Issue: Rotation Job Not Running

**Symptoms:** Rotation statistics show overdue keys

**Solutions:**
1. Check cron job is scheduled: `getScheduledTask()`
2. Verify job logs for errors
3. Manually trigger rotation to test
4. Check KMS quotas haven't been exceeded

### Issue: Database Migration Fails

**Symptoms:** Migration SQL errors

**Solutions:**
1. Check Prisma schema is up to date
2. Verify database connection
3. Run `npm run db:generate` first
4. Check for conflicting column names
